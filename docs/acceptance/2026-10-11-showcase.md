## Found and fixed while building
- The TVPI rule was first described as DPI + RVPI, and the review queue as ordered by reason; both were corrected
  against the code before the content was committed.
- The capability map's spec list stopped at confidence; the platform and corpus specs showed answered questions as
  open; SPEC-evals gave a wrong held-out command and promised a Haiku run that was not made. Each was fixed or noted with
  the product owner's approval, because a reader can now read these documents.
- The held-out history shows the first measurement as stored (4 of 5: one database timeout, re-run unchanged), not
  the cleaned-up "5 of 5" of an older report.
- Two posting browser tests had been failing since policy@3 (an old policy name; literal record versions on a shared
  database); the system behaved correctly. The browser suite now runs with every task.
- Lazy loading broke links to a section on a fresh load; they now wait for the section to appear.

## Known limits
- Build facts are a snapshot (`npm run showcase:facts`), regenerated on purpose and committed.
- The live numbers include demo runs and repeated browser tests; they show activity, not accuracy.
- The contrast check covers text only, not non-text UI contrast (borders, focus rings); no screen reader session was
  run.
- The browser tests run locally (they need the secrets in `.env`); CI runs the unit tests, the build and the eval gate.
