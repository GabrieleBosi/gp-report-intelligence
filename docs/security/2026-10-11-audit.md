# Security audit, 2026-10-11

Before the freeze, two independent passes over the whole system: a fresh-context security review of the code
(OWASP categories plus this stack's specifics) and checks against the live deployment. Result: **no Critical, High or
Medium finding.** Four Low findings were fixed or accepted, each with a test.

## Threat model
A private demo: synthetic data only, every page, function and asset behind Netlify's site password, the browser never
talks to the database (ADR-0003). The realistic attackers are a password holder (a reviewer, or anyone the password
reaches) and a third-party page visited by a browser that has unlocked the site.

## Verified on the live system
| Check | Result |
|---|---|
| Unauthenticated access | 401 for pages, every `/api/*` endpoint (GET and POST), JS assets, `/.env`, `/netlify.toml`, the main-branch host; deploy previews 404 |
| Secrets | the three real secrets (service-role key, Anthropic key, site password) absent from the client bundle, every tracked file and the whole git history; `.env` git-ignored |
| Dependencies | `npm audit`: 0 vulnerabilities (production and dev) |
| Database | RLS on all 11 tables with no policies (deny-all; the service role is server-side only); append-only triggers block update, delete and truncate; functions run with an empty `search_path` and are callable by the service role only; storage buckets private |
| Page headers | strict CSP (scripts from the site only, no inline scripts), `frame-ancestors 'none'`, `X-Frame-Options`, `nosniff`, referrer and permissions policies, HSTS; session cookie `HttpOnly; Secure` |

## Findings
| # | Severity | Finding | Outcome |
|---|---|---|---|
| 1 | Low | **Cross-site POSTs.** The password cookie has no `SameSite` attribute, so in Firefox and Safari a page on another site could make an unlocked browser submit a review decision or an upload. | **Fixed.** Every state-changing endpoint refuses requests the browser marks as cross-site or same-site (`Sec-Fetch-Site`); the JSON endpoints require a JSON content type, which cannot be sent cross-site without a preflight; `/execute` accepts POST only. `core/request-guard.ts`, `e2e/security.spec.ts` |
| 2 | Low | **A crashed run blocked its document.** A run whose function died stayed `running`, and every new run on that document was refused. | **Fixed.** A run request first expires the document's dead runs (queued over 5 minutes, running past the 15-minute function limit), with the reason on the run. Verified live: a run left unstarted was expired after 5 minutes and the next run completed. `core/run-request.ts` |
| 3 | Low | **The daily LLM budget can be exceeded by parallel runs** (each call checks the ledger before the others record their cost). | **Accepted.** Bounded by uploads (30 per hour) and the LLM cache to a few dollars; a reservation in the ledger would need a new database function. |
| 4 | Low | **Database wording shown to a person** (a failed posting returned the database's message). | **Fixed, amended 2026-10-12.** The first fix covered the API response only; the ship review found that the posting log, shown on the run page, still stored the raw text. Both now carry fixed public messages, and the raw text goes to the function log only. The one error stored before the fix is our own simulated-outage text. `publicPostingError` |
| 5 | Info | The upload limit (30 per hour) is site-wide, so one password holder can use it up. | Accepted: by design for a demo. |
| 6 | Info | `/api/metrics` reads seven tables in full on every request. | Accepted at this scale (about 1,500 rows); aggregate in SQL if it grows. |
| 7 | Info | CI actions were pinned to tags. | **Fixed:** pinned to commit hashes (checkout and setup-node v4.4.0, upload-artifact v4.6.2). |
| 8 | Info | Function responses lacked the page headers (`netlify.toml` headers apply to pages only). | **Fixed:** every function responds through one helper with CSP, frame, `nosniff` and referrer headers; a test fails if a function builds a response without it. `netlify/lib/http.ts` |

## Verified sound (no change needed)
Inputs validated with zod (UUIDs, bodies with length caps); run transitions enforced in TypeScript and a database
trigger; no server-side fetch of user-supplied URLs; page images take no path input. Uploads: size before reading,
magic bytes, 20-page cap, duplicates, control and bidirectional characters stripped from file names. The workbook reader
caps inflated output, entries, sheets, cells and text; PDF rendering is clamped to 16 megapixels. Prompt injection: an
upload can never be auto-posted (policy@2), page text cannot forge document tags, outputs are schema-validated, posting
is limited to cleared runs in code and in the database. XSS: the only raw HTML rendering shows the repository's own
Markdown with raw HTML escaped and links restricted; every API string is rendered as text.

## Not verified
A live database diff against the migrations; a screen reader or penetration test by a third party.
