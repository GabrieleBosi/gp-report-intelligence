# Spec: public release

Module id: `public-release` · Depends on: all modules · Status: **approved** 2026-11-14

## Objective
Publish GP Report Intelligence as a public portfolio project: a public GitHub repository and a public live demo that
works with no login, costs $0 on its default path, and cannot be used to spend model budget or change demo data.

The project was built from a case study given in a hiring process. The public version keeps the engineering record
(specs, ADRs, plans, error analyses, the security audit, the eval gate proof) and removes everything that ties it to
that process: the organisation, the role, the dates and logistics, and the audience it was first built for.

**Readers:** recruiters and hiring managers for AI engineer, forward deployed engineer and solutions engineer roles,
who spend about 90 seconds on the README, the demo and one or two files. Engineers who go deeper read the specs and ADRs.

**Not a goal:** new product features, claims about users, traffic or production accuracy.

## Decisions recorded with the product owner (2026-11-14)
1. **New repository, fresh history.** `GabrieleBosi/gp-report-intelligence`, MIT licence. Published as one initial
   commit of the cleaned tree, dated on the day it is made. No backdated or reconstructed history. The README says the
   development history is kept in a private archive. The private repository is not changed.
2. **The process sketch is the author's own work** (nine steps and an improvement loop, drawn in response to the case).
   It stays, described as "my process sketch". Only the generic business problem is described.
3. **Public mode is a static snapshot.** The public site serves recorded runs over the synthetic corpus as static
   files. The review screen works in the visitor's browser and resets on reload. Live runs need the owner's access key.
4. **One site.** The existing Netlify site is renamed to `gp-report-intelligence`. Netlify site-wide password protection
   is removed; the functions check an access key instead. The team stays on Netlify Pro (decided at plan approval: the
   plan covers other projects).
5. **Demo-day material is deleted:** `ops/`, the preflight (`core/preflight.ts`, `scripts/preflight.ts`, its test,
   `npm run preflight`). Plans and the task list stay, with their timelines removed.

### W2. Public mode (ADR-0006)
- **Snapshot export.** `npm run snapshot` (local, owner only: read-only queries with the service key from `.env`)
  writes `public/snapshot/` through the same read adapters the API uses: the 18 corpus documents, every run the site
  links to (the latest run of each document, the tour's runs, the runs behind portfolio records and the review queue)
  with their run views and review state, the review queue, the fund registry, the portfolio with its versions, the
  metrics computed from the exported rows, and PNG page images for the review screen. The upload and its runs are
  left out. Each run keeps its own pipeline version; the banner says these are recorded runs. The snapshot is
  committed; it is synthetic data. Size budget: 10 MB.
  *History of this decision (2026-11-14):* at planning the snapshot was to be generated by replay at one pipeline
  version. At build time that turned out to lose the tour's evidence (the analyst-approved trap and the superseded
  Sonnet run exist only in the live history) and to need in-memory copies of about ten stores. The product owner chose
  the export. The held-out answers copied in T7 keep the eval reproducible from the repository either way.
- **One switch in `src/lib/api.ts`.** By default every function in `api.ts` reads the snapshot. Nothing in the public
  path calls `/api/*`.
- **Review in the browser.** In snapshot mode, accept / fix / reject call the same `decide()` from
  `core/review/actions.ts` and `postRun()` from `core/posting/post.ts`, with in-memory stores. The result shows exactly
  as it does live. State resets on reload.
- **Labelled.** Every page in snapshot mode shows one line: the runs are recorded on a given date, the pipeline is real,
  and actions reset on reload. Upload and "run again" are shown disabled with the reason.
- **Owner access.** An "Owner access" control takes the access key, keeps it in `sessionStorage`, and switches `api.ts` to
  the live functions with `Authorization: Bearer <key>`.
- **Functions.** Every function that has a path checks the key before any database, storage or model call: a
  constant-time comparison against `LIVE_ACCESS_KEY` (at least 32 random characters, set by the owner in Netlify),
  `401` otherwise. The scheduled `keep-alive` has no path and is unchanged. The existing cross-site request guard stays.
- **Backstops if the key leaks:** the daily model cap stays (`DAILY_LLM_BUDGET_USD`), and Netlify code-based rate
  limits per IP: 10 in 3 minutes on `upload` and `run-pipeline-background`, 60 a minute on `runs`, `review` and `post`.
  *Widened to every function at the checkpoint C security review; cut back to these 5 on 2026-11-15, when the live
  site showed that with 11 rules (the Pro plan allows 5 per project) none was enforced.*
- **Database:** no change. Row security stays deny-all; the browser still never talks to Supabase.

## Code style
As in SPEC-platform: logic in `core/`, thin adapters, zod at every boundary, typed results.
```ts
// core/access.ts
export function hasAccess(header: string | null, key: string | undefined): boolean {
  if (!key || key.length < 32 || !header?.startsWith("Bearer ")) return false;
  return timingSafeEqualStrings(header.slice(7), key);
}
```

## Testing strategy
- Unit: `core/access.ts` (missing, short, wrong and correct keys; a missing env var refuses everything).
- Integration: a static test over every function with a path: without the key it answers 401 and calls no database,
  storage or model fake.
- Snapshot: the exported output validates against the same zod schemas the API responses use; the in-browser review
  produces the same outcome as `decide()` for each queued run.
- E2E (local): with the functions stopped, every page renders from the snapshot, a flagged figure can be fixed and
  posted, and the browser makes no `/api/*` request.
- After every step: `typecheck`, `lint`, `test`, `build`, `eval` all pass.

## Boundaries
- **Always:** keep the markers file and `PORTFOLIO-FACTS.md` outside the repository; run the full suite and the eval
  after each step; commit locally in small steps; state eval numbers with n and split.
- **Ask first:** creating the repository, any push, changing visibility, renaming the site, removing the site password,
  changing the Netlify or Supabase plan, linking the site to the new repository, any model spend (including recording
  missing answers), new dependencies, CI changes.
- **Never:** change the private repository or its history; make the private repository public; commit `.env` or
  keys; claim users, traffic or production metrics; add features for appearance; backdate commits.

## Success criteria
1. The markers grep prints nothing over the tree, `src/generated/`, `public/snapshot/` and a fresh `dist/`.
2. gitleaks reports nothing over the public repository's history and tree.
3. `gh repo view GabrieleBosi/gp-report-intelligence --json visibility,licenseInfo` shows PUBLIC and MIT; the history
   is one initial commit plus the gate-proof work, authored with the noreply address.
4. CI on `main` is green: typecheck, lint, test, build, eval gate. The gate-proof pull request is red on the eval gate.
5. `https://gp-report-intelligence.netlify.app` loads with no login. Every page renders from the snapshot; a visitor
   can fix and post a flagged figure; the browser makes no `/api/*` request (checked in the e2e spec and once on the
   live site).
6. Every `/api/*` path answers 401 without the key, and works with it (one live run by the owner, within the cap).
7. The site's previous `*.netlify.app` name no longer resolves to it.
8. The README has every section listed in W3; each eval number in it names n and the split; it contains no em dashes and
   no word from the banned list.
9. `PORTFOLIO-FACTS.md` exists in the private folder, each fact with its source path.
